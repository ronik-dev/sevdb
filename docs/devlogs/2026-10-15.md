## Current Status
- **Build System:** Configured `CMakeLists.txt` for C17 and linked the Criterion testing framework.
- **Project Structure:** Established a standard C library layout with `src/`, `include/`, and `tests/`; isolated mathematical operations into a dedicated `distance.c`/`distance.h` module.
- **Memory Model:** Adopted a "Callee Allocates" (heap) pattern utilizing flexible array members for dynamic vector sizes.
- **Implementation:**
    - Defined `sevdb_vector` and `sevdb_database` structs.
    - Implemented vector memory allocation and deallocation (`sevdb_vector_create`, `sevdb_vector_destroy`).
    - Implemented database memory allocation and deallocation (`sevdb_db_create`, `sevdb_db_destroy`).
    - Implemented database vector insertion and ID-based lookup (`sevdb_db_push_vector`, `sevdb_db_get_vector_by_id`).
    - Implemented database vector removal (`sevdb_db_remove_vector_by_id`), using swap-with-last removal and hash map index updates.
    - Added getters to improve encapsulation of `sevdb_vector` and `sevdb_database` structs.
    - Implemented Euclidean distance calculation (`get_euclidean_distance`).
    - Implemented cosine similarity calculation (`get_cosine_similarity`).
    - Implemented a comparator-based binary heap priority queue (`pqueue`) supporting min-heap and max-heap ordering.
    - Implemented Top-K database retrieval (`sevdb_db_search_k_similar_vectors`) using a linear scan and priority queue to find the most similar vectors based on cosine similarity.
    - Updated similarity search to return similarity scores alongside vectors through the `sevdb_similarity_scored_vector` struct in `types.h`.
    - Implemented basic binary serialization and deserialization (`sevdb_db_serialize`, `sevdb_db_deserialize`), including writing to a temporary file before committing a save and using a checksum.
    - Implemented database capacity growth, including allocation-size checks and initialization of newly allocated vector-pointer slots.
    - Kept ID generation outside the database and implemented duplicate-ID rejection.
    - Implemented an open-addressing `hashmap` with `EMPTY`, `USED`, and `DELETED` slot states to support ID-to-index lookup for the sparse-set-style database storage.
    - Updated `sevdb_db_create`, `sevdb_db_destroy`, `sevdb_db_push_vector`, `sevdb_db_get_vector_by_id`, and `sevdb_db_remove_vector_by_id` to use the hash map.
    - Introduced `sevdb_error` return values for fallible database operations, with distinct error categories including invalid arguments, out-of-memory conditions, full database capacity, duplicate IDs, missing IDs, internal errors, and overflow.
    - Defined ownership behavior for insertion: vector ownership transfers to the database only when `sevdb_db_push_vector` succeeds.
    - Migrated fully to a robust out-parameter pattern using double pointers (**result) and granular state enums (sevdb_state, hm_state, pq_state) for all fallible operations.
    - Hardened API contracts: Output pointers are initialized to NULL before fallible work (e.g., early exits in sevdb_vector_create).
    - Fixed hash map automatic capacity growth by ensuring the insertion index is dynamically recalculated after a rehash.
    - Corrected queue capacity vs. count logical bugs in the Top-K similarity search linear scan.
    - Documented ownership, preconditions, and error semantics for all public APIs via updated Doxygen headers.
- **Testing:**
    - Segmented tests into modular suites (`internal_test_suite`, `distance_test_suite`, `priority_queue_test_suite`, `persistence_test_suite`, and `hashmap_test_suite`).
    - Existing unit tests cover core mathematical functions and data structures.
    - Further testing is needed for allocation failures, and cross-module invariants.

## Next Steps
1. **Performance Profiling & SIMD**: Consider profiling the linear scan and distance calculations. Consider utilizing SIMD instructions (AVX2/AVX-512 or ARM NEON) to vectorize the cosine similarity and Euclidean distance math for significant performance gains on large datasets.
2. **Correctness and Edge-Case Testing:** Expand unit tests for duplicate insertion, removal after swap-with-last operations, capacity growth, hash map collisions and tombstone reuse, and Top-K result ordering. Cover empty databases, mismatched vector dimensions, `k` larger than the number of eligible vectors, and non-finite similarity scores. Run tests with AddressSanitizer and UndefinedBehaviorSanitizer where available.
4. **Serialization Hardening:** Test truncated and corrupted files, malformed headers, unsupported format versions, checksum mismatches, invalid dimensions and counts, and I/O failures. Verify allocation-size checks and cleanup of partially deserialized databases. Document the binary format, versioning, checksum, and portability assumptions.
5. **Parametrization and Configuration (Low Priority):** Define which database settings should be configurable at initialization, such as initial capacity and future search parameters. Establish clear defaults and validation rules without exposing unnecessary implementation details.
6. **C23 Migration (Low Priority):** Consider updating the build standard to C23 when compiler and platform support justify it. Potential improvements include `<stdckdint.h>` for checked integer arithmetic, `[[nodiscard]]` for important return values, `nullptr` for pointer type safety, and modern language features. Keep C17 as the current target until the migration is deliberate and tested.
7. **Multithread Support (Low Priority):** Define the thread-safety model before adding concurrency. Identify which operations may run concurrently and introduce synchronization around shared database, hash map, and priority queue state as required. Test concurrent reads, writes, insertions, removals, and searches for race conditions and data corruption.
